## 一、进程模型

```
┌───────────────────────────── Renderer（React + TS）─────────────────────────────┐
│  src/App.tsx  编排视图、面板、播放器、覆盖层                                      │
│  src/library/ 资料库 v2（core 契约 / suites: grid, bravais, tui / app 运行时）    │
│  src/components/  UI（app / qishui / panelTab / visualizer / command-palette…）  │
│  src/services/    业务服务（onlineMusic/omni、db、coverCache、WE capture…）       │
│  src/stores/      领域状态（播放、视图、音频、主题、壁纸引擎…）                   │
│  src/hooks/       桥接与控制器（播放音频/可视化/交互/更新…）                      │
└───────────────────────────────┬─────────────────────────────────────────────────┘
                                │ preload.cjs（contextBridge）
┌───────────────────────────────┴──────────── Main（Electron CJS）─────────────────┐
│  electron/main.cjs  窗口、IPC、更新、生命周期                                    │
│  音源后端：neteaseBackend / kugouApiBridge / qqBackend / bodianApiBridge /        │
│            qishuiApiBridge + qishui/（签名宿主、扫码、解密代理）                  │
│  壁纸引擎：wallpaperEngineLibrary / Runtime / WindowNative / Window（PowerShell）│
│  其他：audioCachePrune、analysis、modSystem、displaySleepBlocker…                 │
└──────────────────────────────────────────────────────────────────────────────────┘
```

- 渲染层不直接碰平台接口；所有在线音乐业务走 **Omni**（见 `03-核心机制与数据流.md`）。
- 主进程承担：登录/签名、音频解密回环代理、壁纸引擎窗口、更新、系统集成。
- 原生能力通过 `electron/preload.cjs` 暴露；新增 IPC 时同步改 `src/vite-env.d.ts` 的类型。

## 六、必须遵守的架构规则

1. **在线音乐只走 Omni**：普通调用不得直接 import provider 的原始接口；只有 provider adapter/transport 可以碰原始 API。
2. **不把实现继续堆进 `App.tsx`**：新逻辑拆到 hooks / components / stores（见 `skills/file-modularization`）。
3. **高频动画/状态更新**：遵守 `skills/frontend-runtime-guardrails`，避免 rAF/ResizeObserver 里频繁 setState。
4. **优先复用**：歌词时序、文本测量、颜色、i18n、图标、虚拟列表等已有工具，勿重复造轮子。
5. **文件模块化**：入口文件只做装配；复杂函数写简短注释；创建新文件时按仓库约定加文件注释。
6. **测试跟随改动**：纯逻辑加单测；跨面板/视图行为加 UI 测试；不要用构建代替测试。

## 七、测试布局

- 单元：`test/unit/**`，`npm run test:unit`。
- UI：`test/ui/**`，`npm run test:ui`（Playwright，dev server 4173，5 workers，失败重试 1 次）。
- 组件：`test/component/**`，`npm run test:component`。
- 渲染探针：`test/render` / `dev-probes`。
- 改 UI 行为时优先找现成 spec 扩展，避免新建重复用例。

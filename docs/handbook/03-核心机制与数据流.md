# 核心机制与数据流

> 最后核对：2026-10-24 ｜ 对应版本：0.6.11
>
> 这里只写“功能是怎么跑起来的”和“改它要碰哪里”。具体代码以文件为准；结构见 `02-架构与代码地图.md`。

## 一、启动与视图

1. `src/index.tsx` 安装浏览器垫片、日志/调试/帧率限制，然后 `import('./bootstrap')`。
2. `src/bootstrap.tsx` 初始化 i18n、CSS、Folium 模组、原生拖拽守卫，按 URL 挂不同的根：
   - 主界面 `App`
   - 遥控窗口 `RemoteControlApp`
   - OBS 浏览器源（现在播放 / 播放器捕获）
3. `App` 由 `AppSplashGate` 包住，启动体验（引导、更新提示、发布说明）走 `useStartupExperienceGate`。
4. 主视图状态在 `useAppViewStore`：`home` / `player`，以及 `isPanelOpen` 等。
5. 资料库 v2 的界面套件在 `src/library/suites/`：`grid`、`bravais`、`tui`；Lattice 是独立的懒加载视图（`src/components/app/lattice/`），URL hash 为 `#lattice`。

**改视图/导航时注意**：不要用“播放后进入的视图”这种全局偏好来决定歌单点击目标；歌单有统一入口（见第五节）。

## 二、播放与歌词

- 播放状态集中在 `src/stores/usePlaybackStore.ts`（当前歌曲、队列、播放状态、进度等）。
- 主音频元素由播放桥接层维护；`src/hooks/usePlaybackAudioBridge.ts` 负责音频源、缓存、输出设备等。
- 可视化桥 `src/hooks/usePlaybackVisualizerBridge.ts` 把音频时间、歌词时间、当前行索引写进视觉器：
  - 播放中：按音频 `currentTime` 更新。
  - **暂停/跳转**：也要同步主舞台歌词时间与当前行；否则会出现“进度在走、歌词停在 0”的空屏（见 EXP-0008）。
- 视觉器：`src/components/visualizer/`；经典视觉器在 `classic/Visualizer.tsx`。无歌词行时兜底显示歌曲名 + 歌手，不要依赖 `ui.waitingForMusic`（它在所有语言里都是空字符串）。

## 三、在线音乐：Omni 是唯一网关

数据流：

```text
UI / hooks → src/services/onlineMusic/omni.ts → provider adapter → transport → 平台接口
```

- Provider 注册：`src/services/onlineMusic/providerRegistry.ts`。
- 各平台：`neteaseProvider.ts`、`kugouProvider.ts`、`qqProvider.ts`、`bodianProvider.ts`、`qishuiProvider.ts`。
- 普通业务**不得**直接 import provider 的原始接口；只有 adapter/transport 可以碰原始 API。
- 聚合搜索：`federatedSearch.ts`（“全部音源”一次搜遍已登录平台）。
- 自动换源：`crossSourceFallback.ts`（歌曲下架/播放失败时到其他音源找同一首）。
- 元数据归一：`songMetadata.ts`、各 `*Normalize.ts`。
- 队列：跨平台融合在 `usePlaybackStore`；切换平台不清空队列，Lattice 按歌曲来源显示平台徽章。
- 登录/账号：`src/hooks/use*Library.ts`、`src/stores/useOnlineProviderAccountStore.ts`；各平台凭据只在本机。

新增音源的最小改动面：provider/transport/normalize + `providerRegistry` 注册 + 账号/能力声明 + UI 图标/文案。

## 四、汽水音乐

四层结构：

1. **协议层** `electron/qishui/qishui-api.js`
   封装搜索、歌单、播放地址、歌词、用户信息；所有对外请求只从 `requestOfficial` 一个出口出去。
2. **签名宿主** `electron/qishui/qishui-auth-v6.js` + `qishui-auth-v6/`
   主进程隐藏窗口加载官方 Web 安全组件（`bdms.js`、`bdms.node`、`metasecml.dll`），生成 `X-Helios` / `X-Medusa` 等签名头。出口白名单只放行 `api.qishui.com` 与 `api5-lq.qishui.com`。
3. **音频解密 + 本地回环代理** `electron/qishui/qishui-audio-decryptor/` + `electron/qishuiApiBridge.cjs`
   汽水返回密文音频，解密钥在播放地址的 `#auth=`；本机起一个只绑定 `127.0.0.1`、端口随机、路径带随机令牌的小代理，边拉边用 AES-128-CTR 解密，并支持 `Range`（206）。播放器拿到的是普通音频地址。
4. **适配层** `src/services/onlineMusic/qishui*.ts` + `src/hooks/useQishuiLibrary.ts`
   实现 Folia 的音源接口，在 `providerRegistry.ts` 注册后自动出现在音源列表。

其他：

- 扫码登录：`electron/qishui/qishui-qr-login.js`；凭据 `electron/qishui/credentials.cjs`，本机明文，禁止提交/外发。
- 听歌模式：`qishuiFeedModes.ts`、`useQishuiFeedModeStore.ts`；官方图标网格在 `useQishuiFeedModeGridStore.ts`。
- 打包必须对 `qishui-auth-v6/` 做 `asarUnpack`，否则原生模块加载失败（EXP-0010）。
- 官方组件是闭源依赖，官方改协议时音源可能失效，这是外部风险。

## 五、歌单 → 队列 → Lattice（统一语义）

所有歌单入口（首页、播放器侧栏、资料库）共用 `src/library/app/usePlaylistLatticeOpener.ts`：

1. 解析整张歌单资源（本地歌单直接解析；在线歌单走 collection resource）。
2. 资源就绪且补页完成后，**同步**把整张列表写入播放队列，并静默起播。
3. 显式调用 `onOpenLattice()` 进入 Lattice 队列拼贴；不经过集合层压栈，也不受“播放后进入的视图”偏好影响。
4. 交互细节：
   - 250ms 内能完成的打开不闪“加载中”；超过 300ms 才显示提示。
   - 连续点击只让最后一次生效（token + 取消）。
   - 大歌单补页超过 12s，先用已加载部分进入 Lattice。
   - 空歌单/加载失败给出错误提示，不进入空拼贴。

**不要**把歌单入口改回 `openCollection` / Bravais 海报页；专辑、歌手、文件夹仍然走集合页。

## 六、播放器侧栏与快捷控制

- 组件：`src/components/qishui/QishuiPlayerNav.tsx`；模型 `qishuiPlayerNavModel.ts`。
- 显示条件（`App.tsx`）：播放器页 + 有在线账号 + 面板未打开 + 非壁纸模式 + 非鼠标穿透 + 非 Now Playing/PlayerCap 舞台。
- 播放中侧栏会自动隐藏，暂停时保持展开；显隐逻辑在组件内部（离开 650ms 后收起）。改这块时要在实机验证“隐藏后能否被指针重新唤出”，不要只按注释推断。
- 内容：
  - 汽水：推荐、听歌模式、我的音乐、收藏/最近/抖音、创建歌单。
  - 其他平台：快捷控制、全部歌单、收藏/历史（若有）、账号切换；不显示推荐/听歌模式/新建歌单。
- 快捷控制复用面板组件：`src/components/panelTab/controls/PlayerQuickControls.tsx`、`SoundTiles.tsx`、`VolumeRow.tsx`。
- **音频效果器对话框挂在 `App.tsx` 应用层**，不要放回 `ControlsTab`；否则面板收起时点击只会置位、不渲染（EXP-0004）。

## 七、壁纸引擎（WE）

### 7.1 启动与扫描

- 库扫描：`electron/wallpaperEngineLibrary.cjs` 扫描 Steam 库中的 WE 项目；预览通过自定义协议 `folia-we://`。
- 主进程索引在扫描前是空的。应用启动后，如果保存过 WE itemId：
  - 渲染层延迟约 1.2s 调 `refreshLibrary(false)` 预扫描；
  - `wallpaper-engine-start` 和 `folia-we://` 协议还有惰性 `ensureFresh(false)` 兜底；
  - 日志会记录 `unknown-item`。

### 7.2 启动壁纸与会话

- `electron/wallpaperEngineRuntime.cjs` 定位引擎、校验、`openWallpaper`、静音属性。
- 播放窗口由 `electron/wallpaperEngineWindowNative.cjs` 管理（PowerShell 版本是回退）：
  1. 让引擎创建**带边框**窗口（WGC 拒绝创建时无边框的窗口）。
  2. 剥掉边框（`0x94000000`），停靠到屏幕角落。
  3. **发送 `WM_SIZE`**，让引擎按最终客户区重建，消除底部白/黑边（EXP-0001）。
  4. 用 `window:<hwnd>:0` 作为原始捕获源。
  5. 采集流真正活跃后，才加 `WS_EX_TOOLWINDOW | WS_EX_NOACTIVATE` 并隐藏/显示，避免任务栏按钮。
- 监控窗口会重新停靠、处理引擎重启、清理孤儿窗口。

### 7.3 暂停语义

- **音乐暂停不暂停壁纸动画**：只有窗口隐藏/最小化才挂起采集（`windowHidden`）。
- 新采集流首帧未到之前，海报/视频的显隐由 `hasFrame` 控制；视频首帧前 `visibility:hidden`。
- 重挂载时用已采集画面做种子，避免黑屏（EXP-0002）。
- 更细的采集链路与排障见 `docs/wallpaper-engine-background.md`。

## 八、更新

- 通道解析：`electron/updateChannels.cjs`（realeco=latest、limo=beta、cielo=alpha、internal 关闭）。
- 打包元数据由 electron-builder 生成；发布源在 `package.json` → `build.publish`，指向 `2706521883-lgtm/folia-updates`。
- Windows 打包版用 electron-updater；非自动更新环境走手动检查 `latest.yml` 的降级路径（`checkForManualUpdateAvailability`）。
- 更新检查在独立 session（`folia-update-check`），避免刷新代理影响播放。
- **国内镜像尚未实现**：目前仍依赖 GitHub；镜像方案见 `06-约束与决策记录.md`。

## 九、本地库与缓存（简要）

- 本地音乐库、封面缓存、音频缓存：`src/services/db.ts`、`coverCache.ts`、`audioCachePrune.cjs`。
- 本地歌单打开也走统一 opener，但解析的是本地运行时数据（`localCollectionRuntime.ts`）。
- 缓存清理与统计在设置/账户页有入口；不要绕过缓存层直接读文件。

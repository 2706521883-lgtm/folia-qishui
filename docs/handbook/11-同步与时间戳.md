# 同步与时间戳

> 最后核对：**2026-10-24 21:11（UTC+8）**
>
> 作用：让本地、GitHub、桌面镜像、网盘副本按时间对齐。即使中间几天没法同步，也能看出哪份更新、断在哪、该合并什么。

## 一、时间格式

- 统一写成 **`YYYY-MM-DD HH:mm（UTC+8）`**，精确到分钟。
- 不写“今天/昨天/刚才”。
- 跨时区时注明时区；对比时先换成同一时区。
- `05-当前状态与下一步.md` 写“最后核对时间”；`09-会话日志.md` 写“记录时间”；台账写每个副本的“最后更新时间”。

## 二、三副本台账

实际台账写在 `05-当前状态与下一步.md`，格式固定：

| 副本 | 位置 | 最后更新时间 | 版本/commit | 状态 |
|---|---|---|---|---|
| 本地仓库 | `docs/handbook/` | `YYYY-MM-DD HH:mm（UTC+8）` | `abc1234` | 有/无未提交改动 |
| GitHub | `origin/release/<版本>` | `YYYY-MM-DD HH:mm（UTC+8）` | `abc1234` | 已推送/落后/领先 |
| 桌面镜像 | `C:\Users\ZIMO\Desktop\Folia-项目手册` | `YYYY-MM-DD HH:mm（UTC+8）` | 同本地 | 已同步/待同步 |
| 网盘/云盘 | 用户提供 | `YYYY-MM-DD HH:mm（UTC+8）` 或“未记录” | `abc1234` 或“-” | 已备份/未备份/落后 |
| U 盘 | `Folia-便携包` | `YYYY-MM-DD HH:mm（UTC+8）` 或“未记录” | `abc1234` 或“-” | 已复制/未复制 |

规则：

- 没有的副本写“未记录”，**不要猜时间**。
- commit 列记录**最近一次内容提交**；收尾状态提交（只改台账/日志）不重复写，避免每次自引用。远端 HEAD 用 `git ls-remote` 核对。
- U 盘只作为离线副本：先在本地磁盘开发，改完再复制回去；不要直接在 U 盘上跑构建或长期编辑。
- 只要有一份副本的时间晚于台账，就说明中间有改动，先对比再合并。
- 台账是索引，`git log` / `git ls-remote` 是证据。

## 三、取时间与版本

```powershell
# 当前时间
Get-Date -Format "yyyy-MM-dd HH:mm K"

# 本地 HEAD 与提交时间
git rev-parse --short HEAD
git log -1 --format="%h %cI %s"

# 远端 HEAD
git ls-remote origin refs/heads/release/0.6.11

# 桌面镜像最后写入时间
Get-Item "C:\Users\ZIMO\Desktop\Folia-项目手册\00-先读我.md" | Select-Object LastWriteTime
```

Git 的 `%cI` 是 ISO 时间（通常带 UTC 偏移）；写进手册时统一换算成 UTC+8。

## 四、收尾时怎么更新

1. 取当前时间、本地 HEAD、远端 HEAD、桌面镜像时间。
2. 更新 `05` 的台账：每个副本一行，写清时间、commit、状态。
3. 在 `09` 写“记录时间”和同步结果：已推送 `<commit>` / 推送失败原因 / 从哪份同步到哪份。
4. 网盘没有备份就写“未记录”；下次备份后补上时间和版本。
5. 如果发现某副本时间晚于上次台账，先看 `09/05/07` 找出中间改动，再决定合并。

## 五、换电脑 / 在外接手的顺序

1. 读 `05` 台账，记下本地/GitHub/网盘各自的时间和 commit。
2. **时间最晚的副本先看**：它大概率包含中间改动。
3. GitHub 更新 → 先 `git pull`；本地更新 → 先 `git push`；网盘更新 → 先下载对比。
4. 不确定时先备份，再合并；**禁止用旧副本覆盖新副本**。
5. 合并完成后更新台账，并在 `09` 记录“从哪份同步到哪份、合并了什么”。

## 六、断档判断

| 现象 | 含义 | 处理 |
|---|---|---|
| 某副本时间晚于台账 | 中间有未记录改动 | 先对比内容，找出差异 |
| 本地领先、GitHub 落后 | 有提交没推送 | 标“本地领先”，下次先推 |
| GitHub 领先、本地落后 | 有提交没拉取 | 先 `git pull`，再继续 |
| 网盘晚于本地 | 可能在别处改过 | 下载对比，不直接覆盖 |
| 三份时间相同但内容不同 | 有人绕过手册改了文件 | 用 `diff`/`git log` 找差异，补齐记录 |

## 七、合并记录

如果从另一台机器/网盘合并过版本，必须在 `09` 写清：

- 从哪份副本合并（本地/GitHub/网盘）
- 对方最后更新时间与 commit
- 合并了哪些文件/功能
- 合并后的新 commit 与时间

这样下一次接手能沿着时间线看懂“中间那一段”发生了什么，而不是只知道结果。
